# Portability audit and compatibility contract

Status vocabulary: **V** verified source/build observation; **I** architectural inference; **E** requires experiment. No whole engineering assembly has been proved to build on modern cross-platform .NET.

## Ranked obstacles

| Priority / status | Evidence | Implication / containment proposal |
|---|---|---|
| Critical V | `GmshCommon.vcxproj`: CLRSupport, Windows SDK 10, v145 Debug/v143 Release, .lib dependencies; CaeMesh project reference | C++/CLI is not the Mac/Linux bridge. Preserve meshing algorithms but replace the interop boundary, including QMorph extensions. Portable Gmsh itself does not solve this |
| Critical V | NetGenMesher and modified Netgen/QuadWild implementation sources missing; QuadMesher static libraries without matching source | Cannot reproduce required CAD/mesh behavior yet. Recover exact upstream-maintained sources; substitutes require explicit capability gaps, not claims of parity |
| Critical V | `CaeGlobals/Extensions.cs` DeepClone/DumpTo*, Tools.LoadDump*, Controller persistence and commands | BinaryFormatter is used for project files **and ordinary command/model cloning**. Modern .NET migration needs a compatibility plan before splitting assemblies. [Microsoft](https://learn.microsoft.com/en-us/dotnet/core/compatibility/serialization/9.0/binaryformatter-removal) documents that the in-box implementation throws from .NET 9 |
| Critical V/E | ActiViz 5.8 Windows AMD64 references; vtkControl native host and interactor | Preserve VTK algorithms, prove bindings/host/picking before committing frontend architecture. Modern proprietary ActiViz licensing and old-wrapper modernization remain unresolved |
| High V | `Controller.cs` FrmMain field/direct calls; Command.Execute(Controller); RPC BeginInvoke | Controller reuse needs adapters and serialized session ownership, not just a new window. Hidden UI state is part of persistence and command history |
| High V | `CaeGlobals` WinForms editors/hooks/message boxes; CaeModel/CaeResults reference vtkControl; ThreeMF writer consumes actor types | Direction of dependencies crosses the desired core/view boundary. Split/multi-target only documented boundary classes; keep serialized types stable |
| High V | AnalysisJob Run_Win10/Run_OldWin, WMI child-process traversal, ChildProcessJob kernel32; SolverSettings.SetExecutable restricts .exe/.bat/.cmd | Launch/output concepts transfer, lifecycle/detection/validation do not. Implement process service with equivalent cancellation/timeout/status behavior |
| High V | `PrePoMax/Globals.cs` startup paths with backslashes/.exe, python312.dll; Tools startup paths/registry; settings in application folder | Separate immutable assets from user settings and per-run scratch paths; do not treat Windows absolute paths as valid Unix paths |
| High V | RpcServer WindowsIdentity/PipeSecurity, RpcSessionInfoWriter NTFS ACLs, MCP HttpListener | Keep protocol and security semantics, adapt local transport/session-file permissions. HttpListener's required behavior on targets must be tested; Linux pipes are not Windows pipe ACLs |
| Medium V/E | Bitmap/Font/Graphics in vtk widgets/screenshots and UserControls | [System.Drawing.Common](https://learn.microsoft.com/en-us/dotnet/core/compatibility/core-libraries/7.0/system-drawing) is Windows-only. Distinguish primitive Color/Point structs from actual GDI operations; move raster/text operations to view adapters |
| Medium V | Windows batch post-build (`del`, `rd`, robocopy/xcopy), absolute ActiViz paths; PythonApiHelp.targets CodeTaskFactory | Parallel portable build/package targets required; preserving legacy Windows build during transition avoids unnecessary divergence |
| Medium E | culture, case sensitivity, float formatting, file locks, Unicode paths, permissions, line endings, DPI | Add fixtures and platform tests, not global algorithm edits. Model names may be case insensitive while filesystems are not |

Unused System.Windows imports in some element classes and unused vtkControl imports in results files are **review leads**, not proof of an actual runtime dependency. Project references nevertheless pull those assemblies into existing builds. The inventory script reports textual signals without semantic conclusions.

## VTK capabilities and boundaries

The rendering implementation is extensive: `vtkControl/vtkControl.cs` uses prop/point/cell pickers, cell locators and global IDs; `vtkMax/Actor/vtkMaxActor.cs` owns native actor pipelines and element/node mapping. `vtkInteractorStyleControl.cs` implements camera/selection interaction. Four layers hold base, overlay, selection and widget renderers in `vtkControl.Designer.cs`.

Section views use cutters, clipping and custom cap/hatch code under `Tools/SectionViewCap.cs`/`SectionViewHatch.cs`. Result colors/legends use `vtkMax/LookupTable/`, `ColorSpectrum/`, widgets and deformation/animation data. Exports use vtkWindowToImageFilter/PNG/JPEG/TIFF writers and vtkOBJExporter/vtkPolyDataWriter; transparent images and Bitmap conversion add drawing dependencies.

The designer contains `GetXDisplay()` using reflection into Mono's WinForms XplatUIX11 and chooses a generic interactor for X11. This is real historical portability code, but the current Windows-bound projects and DLLs do not establish runnable Mac/Linux support. OnHandleCreated/SetParentId/OnHandleDestroyed, paint reentrancy, resize, event pumping and picking thread ownership are the minimal hosting seam; Win32 wheel messages and PrecisionTouchpad user32/hid handling also need adapters.

**I:** actor/filter algorithms and FEM-to-VTK mappings can plausibly be kept with a compatibility facade and new host. **E:** 5.8→modern VTK API differences, wrapper object lifetime, callbacks, mapper/shader behavior, clipping and multi-layer picking need validation. Replacing only the window is insufficient if the managed binding is unavailable for the target.

Modern [VTK build settings](https://docs.vtk.org/en/v9.5.0/build_instructions/build_settings.html) provide Cocoa/OpenGL and Linux X/EGL/OSMesa options. Apple Silicon is a native architecture target, independent of graphics backend choice. [VTK WebGPU](https://docs.vtk.org/en/v9.6-final/release_details/9.4/add-graphics-backend-preference-for-webgpu-rendering.html) exposes Metal backend selection; this does not prove PrePoMax's old actor/widget/picker stack works on it. Test Cocoa/OpenGL first as a bounded feasibility route; assess WebGPU/Metal separately with identical selection/contour/clipping fixtures. Do not require a rendering-engine rewrite solely because macOS prefers Metal.

## File inventory

| Format | Implementation / contract | Compatibility concerns and tests |
|---|---|---|
| `.pmx` custom project | `Controller.SaveToPmx`: 32-byte program/version header; compressed dump of `{Controller, jobs, tree states, sidePanelsState}` plus FeModel binary data; results stored separately by ResultsCollection | BinaryFormatter graph includes assembly/type names, UI/application types and paths; custom mesh/results binary layout and Deflate framing also matter. Readers before/after version 2_0_6 and uncompressed legacy fallback must be preserved. Test old→new, new→Windows same-baseline, results included/excluded, multi-results, large/truncated files |
| `.pmh` command history, binary journal artifacts | `CommandsCollection.WriteToFile/ReadFromFile`, command.DumpToFile | Command identities/fields and behavior, file-dependent commands, rename binder, undo/redo and regeneration; record source-version semantics, not only successful deserialization |
| `settings.bin` | `SettingsContainer.ToDictionary().DumpToFile`, Tools.LoadDump; includes automation settings/token, solver/work paths | Separate user-private platform settings without silently breaking existing settings import. Never commit tokens. Round-trip reusable settings; explain/remap invalid platform paths |
| Material library `.lib` UI filter | `Forms/41_Material/FrmMaterialLibrary.cs`, serializable MaterialLibraryItem in PrePoMax.Forms | Assembly/type identity and units/material equations; recover historical fixture set. Suffix is not a native shared library in this context |
| Internal `gmshData` and mesh/result binary blocks | GmshCaller uses dump loading; FeMesh/FeModel/FeResults/ResultsCollection WriteTo*/ReadFrom* | Process payload also depends on legacy serialization; keep schema/protocol independent of assembly moves. Check precision, byte order, lengths and version gates |
| `.stl` | STL managed ASCII/binary reader/writer and CaeMesh import | High reuse candidate; verify winding, float precision, units, malformed files and cultures |
| `.step/.stp`, `.iges/.igs`, `.brep` | Custom NetGenMesher/OCCT; geometry strings/metadata in model | Preserve topology IDs/orientation and custom repair/splitting; same file readable does not guarantee same face ordering |
| `.vol`, `.unv`, `.inp`, `.mesh`, `.msh` | Netgen VOL, UNV, CalculiX/Abaqus decks, Medit/MMG, Gmsh; CaeMesh/FileInOut and mesher runners | Element type/order, set/surface labels, second-order node order, precision and IDs; compare semantic connectivity rather than nondeterministic text ordering |
| `.frd`, `.dat`, `.sta`, `.cvg` | CaeResults CalculiX readers, AnalysisJob monitor; OpenFOAM directory files also supported | Fields/history/steps/modes/units, axisymmetric normalization and complex results; preserve raw file fixtures plus parsed values. Status/convergence files are solver artifacts, not project graphs |
| `.3mf`, `.obj`, `.vtk`, images/history text, Python `.py`, run JSON | ThreeMF writer + Lib3MF, renderer exporters, history writers, journal and BatchRunReport | Colors/textures/geometry/export scale, screenshot DPI, script/error/exit contract; export support must be cataloged by actually used writer |

The repository supplies CAD/STL/INP fixtures, but no tracked PMX/PMH/FRD/DAT corpus was found. A corpus from original Windows versions is an early prerequisite. The original Windows application is the reference implementation; it must remain available with pinned application/solver/native hashes.

`RenamedTypeSerializationBinder` already maps selected moved/renamed types and generic arguments. It is a migration aid, not a safe schema, complete compatibility layer or proof that arbitrary assembly relocation is harmless. Keep existing namespaces/assemblies for serialized entities initially. Evaluate a bounded legacy reader plus explicit object graph mapping and compatible writer; a Windows conversion helper may assist transition but cannot satisfy native `.pmx` support as the final product. An unsupported BinaryFormatter package would be a separately reviewed temporary exception, not the recommended permanent solution. Do not change file format or cloning semantics in Phase 0.
