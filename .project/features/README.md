# Feature ideas and improvement proposals

Keep maintainer suggestions here so they survive chat handoffs. These records
describe desired behavior and questions to investigate; they do not schedule
work or authorize production changes. Portability/parity work remains governed
by the roadmap and approved task records.

Use stable IDs (`F001`, `F002`, ...) and descriptive filenames. Each record
captures the original input, scope, evidence, candidate acceptance criteria,
open questions and next review step. Update the existing record as it develops.

Statuses: **Proposed**, **Investigating**, **Approved for a scoped task**,
**Implemented**, **Deferred**, **Declined**. Record the authorization and link
the task before promoting a proposal to implementation. Implementation status
needs verification evidence and its commit; documentation alone is not delivery.
Priority and scheduling remain unset unless the maintainer assigns them.
