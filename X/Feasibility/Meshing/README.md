# Structured meshing feasibility probe

Task 0005: unchanged upstream kernel/header/count/grid types at
`de8f73032a72746e3d6d9afd53d9fbd289eb310a`. Zero production/project/package
dependencies, source edits or namespace stubs. Attribution and licensing remain
in the linked original sources and root LICENSE.

Requires an installed .NET 10 SDK, Python 3 and native C++17 compiler (clang++
or g++). The runner builds only in a disposable temporary directory:

```sh
python3 X/Feasibility/Meshing/run-meshing.py --output .project/reports/structured-meshing/macos-arm64.json
```

The runner verifies source hashes against immutable Git objects and current
bytes, checks the source-link/package closure, then:

- Runs the original C++ checker against all 13 upstream vectors (generated by
  upstream C#, not an independent reference).
- Checks that a changed vector fails and a missing input returns exit 2.
- Runs 17 independent native geometry/count/error checks, including symmetric
  centroid, triangle area, manifold edges/Euler topology, scale/translation,
  evaluator behavior and an exhaustive positive count oracle.
- Runs seven managed count/grid checks and two CLI contracts.
- Compares 1,728 C#/C++ count-contract cases exactly.
- Measures the unchanged full C# mapping/ExceptionTools compile boundary:
  CS0103 for MessageBoxes. The count/grid executable does not include that mapping.

No native CAD engine, full C# mapping, shell-junction feature, live mesher, VTK,
solver, PMX or Windows comparison is claimed. See the
[execution report](../../../.project/reports/structured-meshing-feasibility.md).
